# Gemini에게 일 시키기: 요청문 3개 + 요청문 만드는 법

> 목적: 무료 Gemini(Canvas)로 "분석·시각화 앱"과 "보고서·회의자료"를 만들 수 있는지 시험하고,
> 참가자가 **스스로 이런 요청문을 만드는 법**(결과물을 파헤쳐 거꾸로 쓰는 법)을 배우게 한다.
>
> 같이 쓰는 파일: `시험용_정리된_매출.csv` (앱①이 정리한 결과와 같은 36줄), `정답표.md` (강사용, AI 숫자 대조용)
>
> Gemini의 메뉴 이름과 무료 사용 한도는 자주 바뀌어요. 아래 메뉴 이름은 **확인이 필요한 것**이에요.

---

## 먼저 읽기: 이 문서의 쓰임과 "정답표"를 쓰는 이유

| 절 | 누구를 위한 것 | 무엇 |
|---|---|---|
| 0~5 | **강사** | 무료 Gemini가 믿을 만한지 미리 시험하는 계획서 |
| 6~7 | **참가자** | 요청문을 스스로 만드는 법과 연습 |

**왜 정답표가 있나?** AI는 합계를 틀리거나, 없는 숫자를 지어낼 때가 있어요. 정답을 아는 연습 데이터로 먼저 시험해 봐야 "여기까지는 믿어도 되고, 여기부터는 직접 확인해야 한다"를 알 수 있어요.

**진짜 업무에는 정답표가 없는데?** 그때는 **앱①이 계산한 집계 숫자가 정답표 역할**을 해요. 앱은 같은 입력에 항상 같은 답을 내기 때문이에요. 수업에서 가르칠 습관은 이거예요: **AI가 말한 숫자는 앱①의 숫자와 맞춰 본 다음에 쓴다.**

**데이터 분석·시각화는 어디에 있나?**
- 시각화: 요청문 ① (그래프 앱 만들기), 요청문 ④-3 (그래프 고르고 그리기)
- 분석(무엇을 물을지, 숫자에서 무슨 뜻을 읽을지): **요청문 ④** (④-1 질문 뽑기, ④-2 분석하기)
- 글과 자료로 정리: 요청문 ②, ②-A, ②-B

## 0. 강사 시험 순서 (40분)

| 순서 | 할 일 | 보는 것 |
|---|---|---|
| 1 | 무료 계정으로 Gemini 새 대화를 열고 Canvas를 켠다 (메뉴 이름·위치는 직접 확인) | Canvas가 켜지는지, 한도 안내가 뜨는지 |
| 2 | **요청문 ①**을 붙여넣는다 | 만들기 전에 "화면 계획"을 먼저 말하는지 |
| 3 | 코드가 나오면 화면을 열어 CSV를 넣는다 (파일 고르기, 붙여넣기 둘 다) | 열리는지, 파일/붙여넣기 둘 다 되는지 |
| 4 | **정답표.md**와 화면 숫자를 한 줄씩 대조한다 (아래 5번 표) | 숫자가 정확한지 |
| 5 | 폰 폭(좁은 창)에서 본다. 같은 요청문을 한 번 더 돌려 결과가 같은지 본다 | 글자 크기, 잘림, 매번 다른 결과인지 |
| 6 | **요청문 ②**를 새 대화에 넣어 보고서·회의자료의 **내용**을 만든다 | 숫자를 지어내지 않는지, 검산표가 맞는지 |
| 6-2 | 검산표가 맞으면 **요청문 ②-A**(보고서 웹페이지), **②-B**(회의자료 웹페이지)를 이어서 넣는다 | 읽기 쉬운지, 인쇄(PDF 저장)가 한 쪽씩 깔끔하게 나뉘는지 |
| 7 | (비교용) **요청문 ③**으로 앱 없이 표를 직접 분석시킨다 | 앱을 만들 때와 직접 시킬 때 중 어느 쪽 숫자가 더 정확한지 |
| 8 | **요청문 ④**로 분석을 시킨다 (④-1 질문 뽑기 → ④-2 분석하기 → ④-3 그래프 그리기) | 관찰과 해석을 구분하는지, 숫자 근거를 대는지, 질문에 맞는 그래프를 고르는지 |

**합격 기준(제안):** 정답표와 숫자가 전부 같고, 폰에서 안 잘리고, 오프라인(인터넷 끊고)에서도 열리면 합격.
**NotebookLM은 이번 시험에서 뺐어요.** 제가 알기로 NotebookLM은 글 자료를 모아 요약·질문하는 도구라서 표 계산과 그래프 앱 만들기에는 맞지 않아요. 보고서 재료가 글 자료(회의록, 규정 문서)일 때는 쓸 만할 수 있으니 따로 확인하세요.

## 1. 요청문 ① 분석·시각화 앱 만들기 (Gemini Canvas)

아래 칸 전체를 복사해서 붙여넣으세요. `[ ]`로 된 제목은 AI가 읽기 쉽게 나눈 칸이에요. 지우지 마세요.

```text
[역할]
너는 제조 회사 경영지원팀을 위해 업무용 웹 도구를 만드는 개발자야.
코드를 모르는 직원이 쓸 거라서 화면은 쉽고 큼직해야 해.

[목표]
엑셀에서 정리해 CSV로 저장한 "월별 매출표"를 넣으면, 월별·구분별·품목별·거래처별 합계와 그래프를 한 화면에서 보여 주는 분석 도구를 만들어 줘.
HTML 파일 한 장으로 만들고, 인터넷이 끊겨도 내 컴퓨터에서 돌아가야 해.

[재료: 내가 넣을 데이터]
- CSV 파일이고, 첫 줄은 열 이름이야.
- 열: 일자(예: 2026-07-03) / 거래처(글자) / 구분(수출 또는 내수) / 품목(글자) / 수량(정수) / 금액(원)(정수, 쉼표 없음)
- 지금은 약 40줄이지만, 몇 천 줄이 들어와도 돌아가야 해.
- 첫 3줄 예시:
  일자,거래처,구분,품목,수량,금액(원)
  2026-07-03,Nova Tech,수출,케이블세트,13,117000
  2026-07-04,Sakura Parts,수출,제어보드,77,2695000

[화면 구성: 위에서 아래 순서]
1. 데이터 넣기: [CSV 파일 고르기] 버튼과 "여기에 붙여넣기" 칸. 둘 다 되게 해.
   넣으면 "36줄을 읽었어요 (2026-07-03 ~ 2026-09-27)"처럼 한 줄로 알려 줘.
2. 핵심 숫자 3개를 큰 글씨로: 금액 합계 / 줄 수 / 가장 큰 거래 1건(날짜·거래처·품목·금액).
3. 월별: 막대그래프 + 그 아래 표(월, 금액, 전월 대비 %).
4. 구분별(수출·내수): 가로 막대 + 표(금액, 비중 %).
5. 품목별: 금액이 큰 순서로 가로 막대.
6. 거래처별: 금액이 큰 순서의 표(거래처, 금액, 비중 %, 건수).
7. 맨 아래에 [요약 복사하기] 버튼: 위 숫자들을 글로 정리해서 클립보드에 복사해 줘.

[계산 규칙]
- 합계·비중·증감은 모두 코드로 계산해. 암산하거나 숫자를 지어내지 마.
- 월은 일자의 앞 7글자(예: 2026-07)로 묶어.
- 비중 = 그 항목 금액 ÷ 전체 금액, 소수점 첫째 자리까지 % 로 표시해.
- 전월 대비 = (이번 달 − 지난달) ÷ 지난달, 첫 달은 "-"로 표시해.
- 금액은 쉼표를 넣어 보여 줘. 예: 57,641,000원

[모양 규칙]
- 외부 인터넷에서 가져오는 것(라이브러리, 글꼴, 이미지)을 쓰지 마. 그래프는 직접 그려(SVG 또는 canvas).
- 글자는 18px 이상. 폰(폭 390px)에서도 가로로 잘리지 않게 해.
- 버튼과 안내는 쉬운 한국어로. 영어 용어를 쓰지 마.
- 색은 3가지 이내. 그래프는 색뿐 아니라 글자 이름표도 같이 붙여.

[틀린 데이터가 들어올 때]
- 열이 없거나 숫자가 아닌 값이 있으면 멈추지 말고 빨간 글씨로 "3번째 줄의 금액이 숫자가 아니에요"처럼 알려 줘.

[순서]
1) 먼저 만들 화면 계획을 5줄 이내로 말해 줘.
2) 그다음 Canvas에 코드를 만들어 줘. 계획을 확인받으려고 멈추지 마.

[마지막 검사]
- 화면 맨 아래에 "검산" 칸을 넣어 줘. 월별 합 = 구분별 합 = 품목별 합 = 거래처별 합 = 전체 합이 모두 같으면 "모두 일치", 하나라도 다르면 "불일치"와 어디가 다른지 보여 줘.
```

**시험할 때 일부러 해 볼 것**
- CSV 중간 한 칸의 금액을 `abc`로 바꿔서 넣어 본다 → 빨간 안내가 나오는지.
- 열 이름 하나를 바꿔 본다(예: `구분` → `유형`) → 멈추지 않고 알려 주는지.
- 인터넷을 끊고 열어 본다 → 그래프가 그려지는지(외부 도구를 몰래 쓰면 여기서 드러나요).

## 2. 요청문 ② 보고서·회의자료 만들기

숫자는 AI에게 표를 통째로 주지 않고 **내가 확인한 숫자만** 글로 넘겨요. 아래 숫자는 `정답표.md`의 값이에요.

```text
[역할]
너는 제조 회사 경영지원팀 선배야. 임원에게 보고하는 글을 쉬운 말로, 짧게 쓰는 사람이야.

[목표]
2026년 3분기(7~9월) 매출 집계를 가지고 ① 임원 보고 요약 1쪽 ② 회의 자료 구성안 5장을 만들어 줘.

[재료: 확인된 숫자 (회사 이름은 가짜야)]
- 전체 금액 합계: 57,641,000원 (36건)
- 월별: 7월 18,461,000원 / 8월 20,647,000원 / 9월 18,533,000원
- 구분별: 수출 32,884,000원(57.0%) / 내수 24,757,000원(43.0%)
- 월 × 구분: 7월 수출 8,098,000 · 내수 10,363,000 / 8월 수출 12,007,000 · 내수 8,640,000 / 9월 수출 12,779,000 · 내수 5,754,000
- 품목별: 제어보드 27,020,000 / 전원장치 13,260,000 / 센서모듈 10,692,000 / 케이블세트 6,669,000
- 가장 큰 거래 1건: 9월 13일 Sakura Parts 전원장치 6,136,000원
- 거래처별 1위: Sakura Parts 20,441,000원(35.5%)

[읽는 사람]
- 임원. 바쁘고 숫자를 많이 보고 싶어 하지 않는다. 결론을 먼저 알고 싶어 한다.

[할 일 1: 임원 보고 요약]
- 맨 위에 "한 줄 결론" 1개.
- 3줄 요약.
- 눈에 띄는 점 2가지(숫자 근거를 괄호로 붙여).
- 걱정되는 점 1가지.
- 다음에 할 일 1가지(누가, 언제까지는 비워 둬).

[할 일 2: 회의 자료 구성안 5장]
장마다 아래 4가지를 적어.
- 제목: 결론이 담긴 한 문장 (예: "수출이 내수보다 커졌다")
- 핵심 숫자: 1~2개
- 넣을 그래프: 종류와 무엇을 그릴지
- 발표 메모: 2문장

[규칙]
- 숫자는 위 [재료]에 있는 것만 써. 모르는 숫자는 만들지 마.
- 내가 준 숫자로 새로 계산한 값(증감률 등)은 "계산:"이라고 표시하고 계산식을 같이 적어.
- 이유를 추측한 문장은 "추정:"이라고 표시해. 자료에 없는 일을 사실처럼 쓰지 마.
- 쉬운 말로. 한자어와 영어 용어를 줄여.
- 보고 요약은 한 쪽 이내.

[출력 모양]
## 임원 보고 요약
(위 [할 일 1] 순서대로)
## 회의 자료 구성안
### 1장 ...
### 2장 ...
(5장까지)
## 숫자 검산표
| 글에 쓴 숫자 | 근거(위 재료의 어느 항목) |
(글에 쓴 숫자를 빠짐없이 적고, 근거가 없으면 "근거 없음"이라고 써)

[마지막 검사]
- 답을 보내기 전에 숫자 검산표의 "근거 없음"이 0개인지 확인하고, 있으면 그 문장을 고쳐서 보내.
```

**시험할 때 볼 것:** 검산표를 진짜로 정답표와 대조한다. AI가 "근거 없음 0개"라고 해도 믿지 말고 직접 본다.

### 2-2. 내용을 읽기 좋은 웹페이지로 바꾸고 PDF로 저장하기

요청문 ②로 만든 **내용**(검산표가 맞은 것)을 그대로 두고 모양만 바꿔요. 같은 대화에서 이어서 붙여넣으세요.
PDF는 앱이 만들어 주는 게 아니라, 웹페이지를 연 뒤 **브라우저의 인쇄(Ctrl+P) → "PDF로 저장"** 으로 받아요.
그래서 요청문에 "인쇄했을 때 한 쪽씩 깔끔하게 나뉘는 모양"을 꼭 넣어요.

**요청문 ②-A: 보고서 웹페이지 (A4 세로, 1~2쪽)**

```text
[역할]
너는 임원 보고서를 읽기 좋게 디자인하는 사람이야.

[목표]
바로 위에서 만든 "임원 보고 요약"을 HTML 파일 한 장짜리 보고서 웹페이지로 만들어 줘. 화면에서도 읽기 좋고, 인쇄하면 A4 세로 1~2쪽이 되어야 해.

[재료]
- 위 대화에서 만든 임원 보고 요약과 숫자 검산표의 내용. 글과 숫자는 한 글자도 바꾸지 마.

[화면 구성: 위에서 아래 순서]
1. 맨 위: 제목, 기간(2026년 3분기), 작성 날짜 칸(비워 둠)
2. 한 줄 결론: 큰 글씨, 눈에 띄는 띠 하나
3. 핵심 숫자 3개: 금액 합계 / 수출 비중 / 가장 큰 달
4. 3줄 요약
5. 눈에 띄는 점 2가지: 숫자 근거를 괄호로 같이 보여 주기
6. 월별 막대그래프 1개와 구분별(수출·내수) 비중 그래프 1개
7. 걱정되는 점, 다음에 할 일
8. 맨 아래: 자료 출처 한 줄과 "계산:", "추정:" 표시의 뜻 설명 한 줄

[모양 규칙]
- 외부 인터넷에서 가져오는 것(글꼴, 이미지, 라이브러리)을 쓰지 마. 그래프는 직접 그려(SVG).
- 글자 18px 이상. 색은 3가지 이내. 그래프에는 색만 쓰지 말고 숫자 이름표를 붙여.
- 폰(폭 390px)에서도 가로로 잘리지 않게 해.

[인쇄 규칙]
- 인쇄용 설정(@media print, @page)을 넣어서 A4 세로, 여백 15mm로 나오게 해.
- 인쇄할 때는 배경을 흰색으로 하고 글자는 검정에 가깝게 해. 큰 색 배경은 쓰지 마.
- 그래프, 표, 핵심 숫자 묶음이 쪽 사이에서 잘리지 않게 해(page-break-inside: avoid).
- 화면에서만 보이는 버튼은 인쇄에서 숨겨.
- 맨 위에 작은 안내 한 줄: "PDF로 저장: 키보드 Ctrl+P → 대상에서 'PDF로 저장' 선택". 이 안내는 인쇄에는 안 나오게 해.

[마지막 검사]
- 페이지에 쓴 모든 숫자가 위 검산표의 숫자와 같은지 확인하고, 다르면 고쳐서 보내.
```

**요청문 ②-B: 회의자료 웹페이지 (16:9 가로, 5장)**

```text
[역할]
너는 회의에서 화면으로 보여 줄 자료를 디자인하는 사람이야.

[목표]
바로 위에서 만든 "회의 자료 구성안 5장"을 HTML 파일 한 장짜리 슬라이드 웹페이지로 만들어 줘. 화면에서는 한 장씩 넘겨 보고, 인쇄하면 가로 방향 한 장이 한 쪽이 되어야 해.

[재료]
- 위 대화에서 만든 구성안(장별 제목, 핵심 숫자, 넣을 그래프, 발표 메모)의 내용. 글과 숫자는 바꾸지 마.

[화면 구성]
- 한 장 = 16:9 영역 하나. 장마다 위에 제목(결론 문장), 가운데 핵심 숫자와 그래프, 아래에 작은 글씨로 발표 메모.
- 화면에서는 [이전] [다음] 버튼과 키보드 좌우 화살표로 넘긴다. 몇 장 중 몇 번째인지 표시한다.
- 마지막에 [전체 한 번에 보기] 버튼: 눌렀을 때 5장이 위에서 아래로 모두 나열된다.

[모양 규칙]
- 외부 인터넷에서 가져오는 것을 쓰지 마. 그래프는 직접 그려(SVG).
- 제목 40px 이상, 본문 24px 이상. 한 장에 문장은 3개 이내.
- 색은 3가지 이내, 그래프에는 숫자 이름표를 붙여.

[인쇄 규칙]
- 인쇄할 때 @page로 가로(landscape) 방향으로 하고, 한 장이 정확히 한 쪽이 되게 해(page-break-after: always).
- 인쇄할 때는 모든 장이 나열되어 나오게 하고, [이전][다음] 같은 버튼은 숨겨.
- 발표 메모는 인쇄에서도 보이게 하되 슬라이드 아래에 작은 글씨로.
- 맨 위 작은 안내 한 줄: "PDF로 저장: Ctrl+P → 'PDF로 저장' → 방향 '가로'". 이 안내는 인쇄에는 안 나오게 해.

[마지막 검사]
- 5장에 쓴 숫자가 모두 바로 위 검산표와 같은지 확인하고, 다르면 고쳐서 보내.
```

**시험할 때 볼 것**
- 화면: 폰과 PC에서 읽기 쉬운가, 글자가 잘리지 않는가.
- 인쇄: Ctrl+P 미리보기에서 보고서는 1~2쪽, 회의자료는 5쪽(장당 1쪽)으로 나뉘는가. 그래프가 쪽 사이에서 잘리지 않는가.
- 숫자: 정답표와 같은가.
- **Canvas 미리보기 창에서 인쇄가 막히면** 코드를 복사해 `.html`로 저장한 뒤 그 파일을 브라우저로 열어서 인쇄하세요.
  (Canvas의 보내기/공유 메뉴에 PDF나 문서 내보내기가 있을 수 있지만, 있는지는 직접 확인해야 해요.)

**Canvas와 NotebookLM 스튜디오 중 무엇을 쓰나**

| | Gemini Canvas | NotebookLM 스튜디오 기능 |
|---|---|---|
| 맞는 용도 | 숫자가 들어 있는 보고서·회의자료, 모양을 내가 정하고 싶을 때 | 글 자료(회의록, 규정, 조사 문서)를 모아 요약·정리할 때 |
| 숫자 정확도 | 요청문에 검산 규칙을 넣을 수 있음 | 표 계산에는 약함(제가 알기로). 숫자는 직접 확인 필요 |
| 모양 정하기 | 요청문으로 세세하게 | 정해진 틀에서 고르는 방식(제가 알기로) |
| 이번 수업에서 | **이쪽을 기본으로** | 글 자료 요약용으로 맛보기만 |

> NotebookLM 스튜디오가 만들 수 있는 결과물 종류(보고서, 슬라이드, 인포그래픽 등)는 제가 확실히 알지 못해요. 시험할 때 지금 무료 계정에 어떤 것들이 보이는지 확인해 주세요.

**역공학으로 읽어 보기: 이 요청문은 어디서 나왔나**

| 완성된 결과에서 본 것 | 요청문의 어느 줄 |
|---|---|
| 인쇄하니 그래프가 쪽 사이에서 잘림 | "그래프·표·핵심 숫자 묶음이 쪽 사이에서 잘리지 않게" |
| 인쇄에 파란 배경이 잔뜩 나와 잉크가 낭비됨 | "인쇄할 때는 배경을 흰색으로" |
| 인쇄에 [다음] 버튼이 같이 찍힘 | "화면에서만 보이는 버튼은 인쇄에서 숨겨" |
| 회의자료가 세로로 인쇄됨 | "@page로 가로(landscape)" |
| 장마다 문장이 너무 많아서 읽기 힘듦 | "한 장에 문장은 3개 이내, 본문 24px 이상" |

이 표처럼 **인쇄해서 본 실패 하나가 규칙 한 줄**이 돼요. 5단계 "틀린 곳을 규칙 한 줄로 바꾸기"를 그대로 해 보면 돼요.

## 3. 요청문 ③ (비교용) 앱 없이 표를 바로 분석시키기

`시험용_정리된_매출.csv`를 대화에 첨부하고 아래를 붙여넣어요. 요청문 ①(앱을 만들어 계산)과 **숫자 정확도를 비교**하려는 용도예요.

```text
[역할]
너는 제조 회사의 매출 데이터를 읽는 분석가야.

[재료]
첨부한 CSV. 열: 일자 / 거래처 / 구분 / 품목 / 수량 / 금액(원). 첫 줄은 열 이름.

[할 일]
1. 월별 금액 합계, 구분별 합계와 비중(%), 품목별 합계, 거래처별 합계를 표 4개로 보여 줘.
2. 전월 대비 증감률(%)을 계산해 줘.
3. 눈에 띄는 점 3가지를 쉬운 말로 적어 줘.

[규칙]

- 계산에 코드를 쓸 수 있으면 코드로 계산하고, 못 쓰면 "코드로 확인하지 못했어요"라고 먼저 말해.
- 파일에 없는 사실을 쓰지 마.

[마지막 검사]
- 월별 합 = 구분별 합 = 품목별 합 = 거래처별 합 = 전체 합인지 확인하고 결과를 한 줄로 적어 줘.
```

## 4. 요청문 ④ 데이터 분석하고 시각화하기

**분석**은 "숫자에서 무슨 뜻을 읽어 내는 일"이에요. 그래프를 그리는 건 그 뒤의 일이에요.
순서는 **질문 정하기 → 숫자로 답하기 → 그 답에 맞는 그래프 고르기**예요.

**분석에 쓰는 재료는 원본 파일이 아니라 앱①이 만든 "집계표"로 해요.**
앱은 계산이 정확하고, AI는 읽고 해석하는 데 쓰기 위해서예요. (집계표는 `정답표.md`의 월별·구분별·품목별·거래처별 표와 같은 모양이에요.)

### 4-1. 무엇을 물어볼지 모를 때: 질문 뽑기

데이터 숫자는 아직 주지 않고, **어떤 열이 있는지만** 알려 줘요. AI가 "물어볼 만한 질문"을 뽑아 줘요.

```text
[역할]
너는 제조 회사 경영지원팀의 데이터 분석 선배야.

[재료]
- 2026년 7~9월 매출 자료. 숫자는 아직 보여 주지 않을 거야.
- 열: 일자 / 거래처(5곳) / 구분(수출, 내수) / 품목(4종) / 수량 / 금액(원)

[할 일]
임원이 궁금해할 분석 질문을 10개 뽑아 줘. 아래 6가지 종류를 골고루 섞어.
- 비교: 무엇이 무엇보다 큰가
- 변화: 시간에 따라 어떻게 달라지는가
- 구성: 전체에서 무엇이 얼마나 차지하는가
- 순위: 어디가 1등이고 어디가 꼴찌인가
- 이상한 점: 갑자기 튀거나 빠진 곳이 있는가
- 관계: 두 가지가 같이 움직이는가
질문마다 ① 질문 한 줄 ② 어떤 열로 계산하면 답이 나오는지 ③ 알게 되면 어떤 결정에 도움이 되는지 적어 줘.

[규칙]
- 자료에 없는 열(예: 원가, 이익)이 필요한 질문은 빼거나 "자료에 없음"이라고 표시해.
- 질문은 쉬운 말로, 한 줄로.
```

### 4-2. 숫자에서 뜻 읽기: 분석하기

```text
[역할]
너는 제조 회사 경영지원팀의 데이터 분석 선배야. 임원이 결정할 수 있게 분석해 주는 사람이야.

[재료: 확인된 집계표. 회사 이름은 가짜야]
(여기에 정답표.md의 월별 / 구분별 / 월×구분 / 품목별 / 거래처별 표를 붙여넣기)

[분석 질문]
1. 월별 금액은 어떻게 변했고, 그 변화는 수출과 내수 중 어디에서 왔나?
2. 매출이 가장 큰 품목과 거래처는 무엇이고, 한 곳에 쏠려 있는 위험이 있나?
3. 눈에 띄게 튀거나 이상한 숫자가 있나?

[할 일]
질문마다 아래 4칸으로 답해 줘.
- 관찰: 표에서 눈으로 확인되는 사실만. 숫자를 같이 적어.
- 근거 숫자: 관찰에 쓴 숫자를 표에서 그대로 옮겨 적어. 계산한 값은 "계산:"과 식을 붙여.
- 해석: 왜 그랬을지 생각. 반드시 "추정:"으로 시작하고, 자료에 없는 이유는 사실처럼 쓰지 마.
- 더 확인할 것: 이 해석이 맞는지 알려면 어떤 자료가 더 필요한지.
마지막에 "임원이 오늘 정할 일" 1가지를 제안해 줘.

[규칙]
- 숫자는 [재료]에 있는 것만 써. 모르는 숫자는 만들지 마.
- 관찰, 근거 숫자, 해석을 한 문장에 섞지 마.
- 비율이나 증감은 직접 계산해서 식을 보여 줘.
- 쉬운 말로, 질문마다 5줄 이내.

[마지막 검사]
답에 쓴 모든 숫자를 | 글에 쓴 숫자 | 표의 어느 칸 | 형식의 검산표로 맨 끝에 붙이고, 근거가 없으면 "근거 없음"이라고 써.
```

### 4-3. 질문에 맞는 그래프 고르고 그리기 (Canvas)

그래프는 **질문의 종류에 맞춰** 골라요. 예쁜 것을 먼저 고르면 틀린 이야기를 하게 돼요.

| 질문의 종류 | 맞는 그래프 | 피할 그래프 |
|---|---|---|
| 변화 (시간에 따라) | 꺾은선, 또는 세로 막대(월이 적을 때) | 원그래프 |
| 비교 (여러 개를 견주기) | 막대 | 3차원 그래프 |
| 순위 (1등부터) | 큰 순서로 정렬한 가로 막대 | 원그래프 |
| 구성 (전체에서 얼마나) | 100%로 쌓은 막대 하나 (항목이 4개 이하면 원도 가능) | 항목이 많은 원 |
| 이상한 점 | 막대 + 튀는 값에 이름표 | 점 색만으로 구분 |
| 관계 (둘이 같이 움직이나) | 점 그래프 (각 점이 한 거래) | 막대 두 개 나란히 |

```text
[역할]
너는 숫자를 읽기 쉬운 그래프로 그리는 디자이너야.

[목표]
아래 숫자로 "(질문 한 줄)"에 답하는 그래프 1개를 HTML 한 장으로 만들어 줘.

[재료]
(여기에 그릴 표를 붙여넣기)

[규칙]
- 그래프 종류: (위 표에서 고른 것). 이유를 한 줄로 먼저 말해 줘.
- 막대 그래프의 세로축은 반드시 0부터 시작해. 일부만 잘라서 차이를 부풀리지 마.
- 제목은 질문의 답을 담은 한 문장으로 써. (예: "8월에 매출이 가장 컸다")
- 값 이름표를 막대 끝에 숫자로 붙이고, 단위(원)를 제목 아래에 적어.
- 색은 3가지 이내. 색만으로 구분하지 말고 글자 이름표도 같이 붙여.
- 외부 인터넷에서 가져오는 것을 쓰지 말고 그래프는 직접 그려(SVG).
- 글자 18px 이상. 폰(폭 390px)에서도 잘리지 않게 해.
- 표에 없는 숫자는 만들지 마.

[마지막 검사]
그래프에 그린 모든 값이 [재료]의 숫자와 같은지 확인하고, 다르면 고쳐서 보내.
```

**시험할 때 볼 것**
- ④-1: 질문이 6종류로 고르게 나오는가, 자료에 없는 열(원가, 이익)을 걸러 내는가.
- ④-2: 관찰·근거·해석이 나뉘어 있는가. "추정:" 표시를 지키는가. 검산표가 정답표와 맞는가.
  - 정답표로 확인할 분석 포인트: 8월 +11.8%는 수출이 늘어서(7월→8월 수출 +3,909,000, 내수 −1,723,000), 9월 −10.2%는 내수가 줄어서(8월→9월 내수 −2,886,000)예요. 제어보드가 품목 1위(46.9%), Sakura Parts가 거래처 1위(35.5%)예요.
- ④-3: 변화 질문에 원그래프를 고르지 않는가, 막대의 세로축이 0부터인가, 그래프 값이 표와 같은가.

**역공학으로 읽어 보기: 이 요청문은 어디서 나왔나**

| 결과에서 본 실패 | 요청문의 어느 줄 |
|---|---|
| 질문이 "수출과 내수 비교"만 10개 나옴 | "6가지 종류를 골고루 섞어" |
| 분석이 "8월에 올랐다. 신제품 효과 같다"처럼 섞여 나옴 | "관찰, 근거 숫자, 해석을 한 문장에 섞지 마", "해석은 '추정:'으로 시작" |
| 자료에 없는 원인을 사실처럼 씀 | "자료에 없는 이유는 사실처럼 쓰지 마" |
| 막대 그래프가 8월을 부풀려 보이게 함 | "세로축은 반드시 0부터" |
| 변화 질문에 원그래프를 줌 | "그래프 종류와 이유를 먼저 말해 줘" + 질문 종류별 그래프 표 |

## 6. 요청문 만드는 법: 결과물을 파헤쳐 거꾸로 쓰기 (참가자용)

### 한 줄로
**좋은 요청문은 "결과물의 설명서"를 거꾸로 쓴 것이에요.**
완성된 결과를 부품으로 쪼개고, 부품마다 "이걸 시키려면 뭐라고 말해야 하지?"를 적으면 요청문이 돼요.

앞의 요청문 ①이 어떻게 나왔는지, 아래 순서로 거꾸로 따라가 봅니다.

### 1단계. 결과물을 눈으로 훑어서 "부품 목록" 만들기

완성된 앱 화면을 보면서 5가지로 나눠 적어요.

| 칸 | 물어볼 것 | 앱 예시 |
|---|---|---|
| A. 영역 | 화면이 위에서 아래로 어떤 덩어리인가? | 데이터 넣기 → 핵심 숫자 3개 → 월별 → 구분별 → 품목별 → 거래처별 → 복사 버튼 |
| B. 눌러서 되는 것 | 버튼, 입력칸은 무엇인가? | 파일 고르기, 붙여넣기 칸, 요약 복사하기 |
| C. 숫자 | 어떤 숫자가 어떻게 계산되어 나오나? | 합계, 비중 %, 전월 대비 % |
| D. 겉모습 | 글자 크기, 색, 폰에서의 모양은? | 큰 글씨, 색 3가지, 폭 390px |
| E. 안 보이지만 필요한 약속 | 인터넷 없이 되나? 틀린 데이터가 오면? | 외부 도구 금지, 빨간 안내 |

> 💡 **팁:** 화면에 안 보이는 것(E)이 제일 빠지기 쉬워요. 빠지면 AI가 마음대로 정해요.

### 2단계. 부품마다 "시키는 문장"으로 바꾸기

막연하게 말하면 AI가 마음대로 채워요. 아래처럼 **명사와 동사와 숫자**로 바꿔요.

| 부품 | 막연한 말 (나쁨) | 구체적인 말 (좋음) |
|---|---|---|
| 핵심 숫자 | "요약 숫자도 보여 줘" | "핵심 숫자 3개를 큰 글씨로: 금액 합계 / 줄 수 / 가장 큰 거래 1건(날짜·거래처·품목·금액)" |
| 비중 | "비율도 알려 줘" | "비중 = 그 항목 금액 ÷ 전체 금액, 소수점 첫째 자리까지 %" |
| 글자 | "글씨 크게" | "글자는 18px 이상" |
| 폰 | "모바일도 되게" | "폭 390px에서 가로로 잘리지 않게" |
| 틀린 데이터 | "오류 처리 해 줘" | "금액이 숫자가 아니면 멈추지 말고 '3번째 줄의 금액이 숫자가 아니에요'라고 빨간 글씨로 알려 줘" |

**고치는 요령 3가지**
1. "크게, 예쁘게, 잘, 적당히"는 **재 볼 수 있는 말**로 바꾼다. (18px, 3가지, 소수점 첫째 자리)
2. 숫자 계산은 **식을 같이 적는다.** (비중 = 항목 ÷ 전체)
3. "해 줘"만 쓰지 말고 **"하지 마"도 쓴다.** (지어내지 마, 외부 인터넷 쓰지 마)

### 3단계. 6칸 틀에 옮겨 담기

부품 문장들을 아래 6칸으로 나눠 담으면 요청문이 완성돼요.

| 칸 | 한 줄 설명 | 요청문 ①에서 |
|---|---|---|
| [역할] | AI가 누구인지, 읽는 사람이 누구인지 | "제조 회사 경영지원팀을 위해 도구를 만드는 개발자, 코드를 모르는 직원이 쓴다" |
| [목표] | 끝났을 때 무엇이 있어야 하나 (한 문장) | "CSV를 넣으면 합계와 그래프를 한 화면에 보여 주는 도구, HTML 한 장" |
| [재료] | AI에게 주는 자료와 그 설명 | 열 이름 6개와 뜻, 첫 3줄 예시 |
| [할 일] | 화면 구성 / 계산 방법 (1단계의 A, B, C) | 화면 7개 영역, 계산 규칙 |
| [규칙] | 겉모습과 약속, 하지 말 것 (D, E) | 글자 18px, 외부 인터넷 금지, 쉬운 한국어 |
| [마지막 검사] | 끝났는지 **스스로 확인하는 방법** | 검산 칸: 월별 합 = 구분별 합 = … |

**빈칸 카드 (복사해서 채워 쓰세요)**

```text
[역할]
너는 (누구)를 위해 (무엇)을 만드는 (직업)이야. 읽는/쓰는 사람은 (누구)야.

[목표]
(결과물 이름)을 만들어 줘. 끝나면 (무엇이 되어 있어야 하는지).

[재료]
- 내가 줄 자료: (어떤 모양)
- 자료의 열/항목: (이름과 뜻을 하나씩)
- 예시 3줄:

[할 일]
1. (화면/글의 첫 번째 덩어리)
2. (두 번째 덩어리)
3.
(계산이 있으면) 계산 규칙: ○○ = △△ ÷ □□

[규칙]
- 꼭 지킬 것: (재 볼 수 있는 말로)
- 하지 말 것: (지어내지 마 / 외부 인터넷 쓰지 마 / 영어 용어 쓰지 마)
- 모르면: (물어보지 말고 "자료에 없음"이라고 써 줘)

[마지막 검사]
끝내기 전에 (무엇)을 확인하고, 안 맞으면 (어떻게 하라).
```

### 4단계. 돌려 보고, 틀린 곳을 "규칙 한 줄"로 바꾸기

처음부터 완벽한 요청문은 없어요. **틀린 곳이 나오면 그걸 막는 규칙을 한 줄 더하세요.** 이것이 요청문을 키우는 방법이에요.

| 이렇게 틀렸다 | 왜 그랬을까 | 더할 규칙 한 줄 |
|---|---|---|
| 합계가 정답과 다르다 | AI가 암산했다 | "모든 합계는 코드로 계산해. 암산하지 마." |
| 없는 숫자가 보고서에 나온다 | 모르는 걸 채워 넣었다 | "숫자는 [재료]에 있는 것만 써. 모르면 '자료에 없음'." |
| 폰에서 가로로 잘린다 | 폭을 안 정했다 | "폭 390px에서 가로 스크롤이 생기지 않게 해." |
| 인터넷 끊으니 그래프가 안 보인다 | 외부 그래프 도구를 가져다 썼다 | "외부 인터넷에서 가져오는 것을 쓰지 마. 그래프는 직접 그려." |
| 날짜가 달라 월별 묶음이 틀리다 | 날짜 모양을 안 알려 줬다 | "일자는 2026-07-03 모양이야. 월은 앞 7글자로 묶어." |
| 쉼표 있는 숫자가 계산에서 빠진다 | 쉼표 모양을 안 알려 줬다 | "금액은 쉼표 없는 정수야. 쉼표가 있으면 지우고 계산해." |
| 영어 버튼이 나온다 | 말투를 안 정했다 | "버튼과 안내는 쉬운 한국어로. 영어 용어 금지." |
| 열 이름이 다르면 멈춘다 | 틀린 데이터를 생각 안 했다 | "열이 없으면 멈추지 말고 어떤 열이 없는지 빨간 글씨로 알려 줘." |

> 💡 **기록하는 습관:** 틀린 곳과 더한 규칙을 메모장에 모으세요. 그게 **나만의 규칙 사전**이 돼요. 다음 요청문에 그대로 가져다 쓰면 돼요.

### 5단계. AI에게 "거꾸로 물어보기" (진짜 역공학)

마음에 드는 결과물이 이미 있으면(내가 만든 것, 동료가 만든 것, 인터넷에서 본 것), AI에게 **그 결과를 만든 요청문을 짐작해 달라고** 할 수 있어요.

```text
[역할]
너는 결과물을 보고 그것을 만든 요청문을 거꾸로 짐작하는 전문가야.

[재료]
(아래에 결과물을 붙여넣기: 완성된 화면의 설명, 화면 캡처, 또는 HTML 코드)

[할 일]
1. 결과물을 부품으로 쪼개서 표로 보여 줘: 영역 / 눌러서 되는 것 / 숫자 계산 / 겉모습 / 안 보이는 약속.
2. 이 결과물을 다시 만들려면 어떤 요청문이 필요한지 [역할] [목표] [재료] [할 일] [규칙] [마지막 검사] 6칸으로 써 줘.
3. 요청문에서 "이 줄을 빼면 결과가 어떻게 달라질지"를 줄마다 한 문장으로 설명해 줘.

[규칙]
- 결과물에서 눈으로 확인되는 것만 근거로 써. 짐작이면 "짐작:"이라고 표시해.
- 요청문의 모든 기준은 재 볼 수 있는 말로 써(px, 개수, 소수점 자리).
```

**꼭 기억하세요**
- AI가 써 준 요청문은 **가설**이에요. 그대로 믿지 말고, **그 요청문으로 다시 만들어서 원래 결과와 비교**하세요. 달라진 곳이 요청문에서 빠진 부분이에요.
- 비교해서 빠진 곳을 찾아 규칙 한 줄로 더하면 4단계와 똑같아요.

### 6단계. 한 번에 다 시키지 말고, 작게 시작해서 키우기

요청문 ①은 길어 보이지만, 처음부터 이렇게 쓴 게 아니에요. 이렇게 키웠어요.

| 버전 | 시킨 것 | 요청문 모양 |
|---|---|---|
| v1 | CSV를 넣으면 금액 합계만 | 아주 짧게 (역할, 목표, 재료만) |
| v2 | 월별 막대그래프 추가 | "지금 도구에 월별 막대그래프만 더해 줘. 나머지는 그대로 둬." |
| v3 | 구분별·품목별 추가 | 같은 방식으로 한 가지씩 |
| v4 | 요약 복사 버튼, 검산 칸 | 같은 방식으로 |
| v5 | 내 업무 열 이름에 맞게 고치기 | "열 이름을 이렇게 바꿔 줘: ..." |

> 💡 **"나머지는 그대로 둬"** 를 꼭 붙이세요. 안 그러면 AI가 잘 되던 곳까지 고쳐 버려요.

### 7단계. 다 쓴 요청문 자가 점검 (4가지)

| 질문 | 아니면 |
|---|---|
| 이 요청문을 처음 보는 사람이 읽어도 같은 결과를 만들 수 있나? | 빠진 설명을 [재료]와 [할 일]에 더한다 |
| 결과가 맞는지 **숫자나 눈으로 잴 수 있나?** | "크게"를 "18px"로, "정확히"를 "검산 칸"으로 바꾼다 |
| "하지 말 것"이 한 줄이라도 있나? | 지어내기, 외부 인터넷, 영어 용어 중 필요한 것을 더한다 |
| 끝났는지 AI가 **스스로 확인하는 방법**이 있나? | [마지막 검사]에 한 줄 더한다 |

## 7. 참가자 연습 미션 (15분)

1. **고르기:** 오늘 만든 앱①의 합계 화면, 또는 내가 자주 보는 보고서 한 장을 고른다.
2. **쪼개기:** 1단계 표(영역 / 눌러서 되는 것 / 숫자 / 겉모습 / 안 보이는 약속)를 채운다. (5분)
3. **옮겨 담기:** 빈칸 카드의 6칸에 옮겨 쓴다. 막연한 말에는 숫자와 식을 붙인다. (5분)
4. **돌려 보기:** Gemini에 붙여넣어 결과를 본다. 틀린 곳 한 가지를 찾아 규칙 한 줄을 더하고 다시 돌린다. (5분)
5. **나누기:** 더한 규칙 한 줄을 옆 사람에게 읽어 준다. 그 줄이 어떤 실패를 막는지도 같이 말한다.

**미션 기록표**

| 내가 쪼갠 부품 (1단계) | 시키는 문장 (2단계) | 틀린 곳 | 더한 규칙 한 줄 |
|---|---|---|---|
| | | | |
| | | | |
